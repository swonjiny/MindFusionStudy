# 02-03 Factory 방식 노드 생성

## 1. 학습 목표

설치된 4.9.1 버전의 `diagram.factory.createShapeNode`를 사용한다.

## 2. 완성 화면

초록 계열의 `Factory 생성` 노드 한 개가 표시된다.

## 3. 선수 지식

02-01의 직접 생성과 등록 과정을 알아야 Factory의 단축 효과를 이해할 수 있다.

## 4. 이번 단계에서 사용하는 객체

`Diagram.factory`, `Factory.createShapeNode`, `ShapeNode`를 사용한다.

## 5. 핵심 개념

Factory 메서드는 생성과 Diagram 등록을 동시에 수행한다. 반환 노드에 `addItem`을 다시 호출하지 않는다.

## 6. 파일 구성

`Step0203FactoryNode.jsx`, `lessonDefinitions.js`의 `factoryNode` helper, API 조사 문서를 함께 참고한다.

## 7. 구현 순서

factory 접근 → 좌표 네 개로 createShapeNode 호출 → 반환 노드 스타일 설정 → 노드 수 검증 순서다.

## 8. 전체 소스 코드

```js
const node = diagram.factory.createShapeNode(55, 42, 58, 28);
node.text = "Factory 생성";
node.brush = "#e8f8ef";
node.stroke = "#289766";
```

## 9. 소스 코드 상세 설명

현재 설치 선언은 Rect 한 개 또는 x, y, width, height 숫자 네 개를 허용한다. 생성 직후 nodes 컬렉션에 포함된다.

## 10. 실행 흐름

Factory가 ShapeNode 생성 → 기본값 복사 → Diagram 등록 → 반환 → 사용자 스타일 설정 순서로 처리한다.

## 11. 상태와 데이터 흐름

Factory는 해당 Diagram을 내부에 보관하므로 결과 노드는 자동으로 같은 Diagram의 nodes에 들어간다.

## 12. 정상 실행 기준

Factory 노드 1개가 표시되고 nodes.length가 1이며 연결선과 오류가 없어야 한다.

## 13. 자동 검증 방법

다시 실행을 여러 번 눌러도 검증 패널이 계속 1개인지 확인한다.

## 14. 수동 확인 항목

노드를 드래그할 수 있고 초록 배경 및 테두리가 표시되는지 확인한다.

## 15. 자주 발생하는 오류

반환 노드를 `diagram.addItem(node)`에 다시 전달하면 중복 등록 위험이 있다.

## 16. 오류 해결 과정

Factory 호출 직후 nodes.length를 확인한다. 이미 1이면 addItem을 호출하지 않는다.

## 17. 이전 단계와 비교

직접 생성의 constructor와 addItem 두 단계를 Factory 호출 한 번으로 줄였다.

## 18. 다음 단계

02-04에서 직접 생성 방식만 분리해 각 단계의 책임을 다시 확인한다.

## 19. 연습 문제

Rect 객체를 인자로 넘기는 형태로 바꾸고 결과가 같은지 검증한다.

## 20. 핵심 요약

Factory는 표준 항목을 빠르게 만들고 등록한다. 자동 등록 여부를 실제 버전 기준으로 확인해야 한다.
