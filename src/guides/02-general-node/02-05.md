# 02-05 Factory와 직접 생성 방식 비교

## 1. 학습 목표

두 생성 방식을 같은 Diagram에서 사용하고 등록 책임 차이를 비교한다.

## 2. 완성 화면

초록 Factory 노드와 주황 직접 생성 노드가 나란히 표시된다.

## 3. 선수 지식

02-03과 02-04의 생성 코드 및 자동 등록 여부를 이해해야 한다.

## 4. 이번 단계에서 사용하는 객체

`Factory`, `ShapeNode`, `Rect`, `Diagram.addItem`을 함께 사용한다.

## 5. 핵심 개념

최종 결과는 둘 다 ShapeNode지만 생성 과정과 등록 책임이 다르다.

## 6. 파일 구성

`Step0205CreationComparison.jsx`와 두 helper인 `factoryNode`, `directNode`를 사용한다.

## 7. 구현 순서

Factory 노드 생성 → 직접 노드 생성 → 직접 노드만 addItem → 색상 구분 → 노드 수 2 검증 순서다.

## 8. 전체 소스 코드

```js
const factory = diagram.factory.createShapeNode(24, 42, 55, 28);
const direct = new ShapeNode(diagram);
direct.bounds = new Rect(92, 42, 55, 28);
diagram.addItem(direct);
```

## 9. 소스 코드 상세 설명

Factory 반환값은 즉시 등록되어 있고 direct 객체는 addItem 전까지 컬렉션 밖에 있다.

## 10. 실행 흐름

Factory 경로와 직접 경로가 각각 한 노드를 만든 뒤 같은 nodes 배열에 합류한다.

## 11. 상태와 데이터 흐름

각 helper 반환 배열은 조작 편의를 위한 것이고 실제 렌더링 데이터는 Diagram nodes 배열이다.

## 12. 정상 실행 기준

두 노드가 겹치지 않고 노드 수 2, 연결선 0, 오류 0이어야 한다.

## 13. 자동 검증 방법

재실행을 반복해도 nodes.length가 2를 넘지 않는지 확인한다.

## 14. 수동 확인 항목

색과 라벨로 두 생성 경로가 구분되는지 확인한다.

## 15. 자주 발생하는 오류

두 노드 모두 addItem 하거나 둘 다 생략하면 중복 또는 누락이 발생한다.

## 16. 오류 해결 과정

각 생성 직후 nodes.length 변화를 기록하면 어느 호출이 등록까지 수행하는지 알 수 있다.

## 17. 이전 단계와 비교

앞선 두 단계를 한 화면에 합쳐 코드와 결과의 관계를 직접 비교한다.

## 18. 다음 단계

02-06에서는 생성된 노드의 x, y 좌표를 동적으로 변경한다.

## 19. 연습 문제

Factory 노드도 직접 생성 방식으로 바꾸고 addItem 호출 수가 정확한지 검증한다.

## 20. 핵심 요약

두 방식의 결과 타입은 같지만 Factory는 자동 등록, 직접 생성은 명시적 등록이다.
