# 02-06 노드 위치 변경

## 1. 학습 목표

노드 bounds의 x, y를 읽고 새 Rect로 위치를 변경한다.

## 2. 완성 화면

현재 x, y, width, height가 Tag로 표시되고 버튼을 누르면 노드가 오른쪽 아래로 이동한다.

## 3. 선수 지식

02-04의 직접 생성과 Rect의 네 인자 의미를 알아야 한다.

## 4. 이번 단계에서 사용하는 객체

`ShapeNode.bounds`, `Rect.x`, `Rect.y`, 새 `Rect` 인스턴스를 사용한다.

## 5. 핵심 개념

bounds는 위치와 크기를 한 객체에 담는다. 위치만 바꿀 때 기존 width와 height를 보존한다.

## 6. 파일 구성

`Step0206NodePosition.jsx`와 `DiagramLesson.jsx`의 `moveNode` 함수가 핵심이다.

## 7. 구현 순서

첫 노드 조회 → 기존 bounds 읽기 → x+15, y+10 계산 → 새 Rect 할당 → 검증/화면 값 갱신 순서다.

## 8. 전체 소스 코드

```js
const node = diagram.nodes[0];
node.bounds = new Rect(
  node.bounds.x + 15,
  node.bounds.y + 10,
  node.bounds.width,
  node.bounds.height,
);
```

## 9. 소스 코드 상세 설명

기존 Rect를 직접 부분 수정하기보다 새 Rect를 할당하면 라이브러리의 변경 알림과 repaint가 명확해진다.

## 10. 실행 흐름

버튼 클릭 → nodes[0] 조회 → 좌표 계산 → bounds setter → 화면 repaint → metrics state 갱신 순서다.

## 11. 상태와 데이터 흐름

실제 좌표는 Diagram 노드에 있고 React state는 화면에 보여 줄 스냅샷만 저장한다.

## 12. 정상 실행 기준

버튼마다 x가 15, y가 10 증가하고 width/height는 유지되어야 한다.

## 13. 자동 검증 방법

노드 수 1 검증 후 버튼 전후 Tag 텍스트가 달라지는지 Playwright로 검사할 수 있다.

## 14. 수동 확인 항목

노드가 이동하며 잘리거나 실행 영역 밖으로 즉시 사라지지 않는지 확인한다.

## 15. 자주 발생하는 오류

x, y 대신 width, height를 변경하거나 좌표 단위를 CSS 픽셀로 오해할 수 있다.

## 16. 오류 해결 과정

버튼 전후 bounds 네 값을 모두 표시하고 바뀌어야 할 두 값만 변하는지 비교한다.

## 17. 이전 단계와 비교

02-05까지는 생성 시 위치가 고정됐다. 이번 단계는 실행 중 bounds를 변경한다.

## 18. 다음 단계

02-07에서 같은 bounds 객체의 width와 height를 변경한다.

## 19. 연습 문제

왼쪽 위로 이동하는 버튼을 추가하고 좌표가 음수가 되지 않게 제한한다.

## 20. 핵심 요약

위치 변경은 새 Rect에 변경된 x, y와 보존된 width, height를 담아 bounds에 할당한다.
