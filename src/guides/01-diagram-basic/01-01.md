# 01-01 빈 Diagram 화면

## 1. 학습 목표

`Diagram` 모델을 만들고 React `DiagramView`로 빈 canvas를 표시한다. 노드가 없어도 뷰가 정상인지 검증한다.

## 2. 완성 화면

연한 파란 배경, 빈 화면 안내 오버레이, 현재 픽셀 크기와 확대 비율이 표시된다.

## 3. 선수 지식

React 함수 컴포넌트, `useState`, 부모와 자식의 CSS 높이 관계를 알고 있으면 충분하다.

## 4. 이번 단계에서 사용하는 객체

| 객체 | 역할 |
| --- | --- |
| `Diagram` | 노드와 연결선을 보관하는 모델 |
| `DiagramView` | Diagram을 canvas에 렌더링하는 React 래퍼 |

## 5. 핵심 개념

모델과 뷰는 분리되어 있다. `new Diagram()`만으로 화면은 생기지 않으며 `<DiagramView diagram={diagram} />`가 필요하다.

## 6. 파일 구성

- `Step0101EmptyDiagram.jsx`: 독립 예제 진입점
- `DiagramLesson.jsx`: Diagram 생성, 도구막대, 검증 전달
- `lessonDefinitions.js`: 예제별 초기화
- `diagram.css`: 최소 500px 실행 영역

## 7. 구현 순서

1. lazy state로 Diagram을 한 번 만든다.
2. 초기화 전에 `clearAll()`을 호출한다.
3. DiagramView에 모델을 전달한다.
4. 부모에 500px 이상의 높이를 준다.
5. `diagram.nodes.length === 0`을 검증한다.

## 8. 전체 소스 코드

```jsx
const [diagram] = useState(() => new Diagram());
useEffect(() => {
  diagram.clearAll();
  return () => diagram.clearAll();
}, [diagram]);
return <DiagramView diagram={diagram} />;
```

## 9. 소스 코드 상세 설명

lazy initializer는 렌더링 때마다 새 모델을 만들지 않는다. cleanup에서 내용만 비우고 core view의 dispose는 React 래퍼에 맡긴다.

## 10. 실행 흐름

컴포넌트 생성 → Diagram 생성 → effect 초기화 → DiagramView가 canvas 연결 → 검증 상태 보고 순서다.

## 11. 상태와 데이터 흐름

예제는 `onStatus`로 `diagramReady`, `viewReady`, `nodeCount`, `linkCount`를 부모 검증 패널에 전달한다.

## 12. 정상 실행 기준

Diagram과 DiagramView가 존재하고, 노드 0개, 연결선 0개, 콘솔 오류 0개여야 한다.

## 13. 자동 검증 방법

검증 패널의 `노드 개수`가 `0개`이고 모든 항목이 `success`인지 확인한다.

## 14. 수동 확인 항목

실행 영역 높이가 500px 이상인지, 연한 파란 배경과 안내 문구가 잘리지 않는지 확인한다.

## 15. 자주 발생하는 오류

부모 높이가 없으면 `height: 100%`인 DiagramView의 계산 높이가 0이 되어 보이지 않는다.

## 16. 오류 해결 과정

개발자 도구에서 `.diagram-host`와 `.mf-react-diagram`의 계산 높이를 차례로 확인하고 부모부터 높이를 지정한다.

## 17. 이전 단계와 비교

첫 구현 단계이므로 비교 대상이 없다. 이후 모든 단계가 이 모델과 뷰 구조를 재사용한다.

## 18. 다음 단계

01-02에서는 고정 높이와 화면 채우기 방식을 비교하고 `ResizeObserver`로 실제 영역 크기를 표시한다.

## 19. 연습 문제

최소 높이를 600px로 바꾸고 모바일 미디어 쿼리에서는 480px로 줄여 본다.

## 20. 핵심 요약

Diagram은 모델, DiagramView는 화면이다. 뷰의 부모 높이와 빈 모델의 실제 노드 수를 함께 확인한다.
