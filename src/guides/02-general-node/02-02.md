# 02-02 일반 노드 2개 생성

## 1. 학습 목표

여러 ShapeNode를 독립적으로 생성하고 서로 겹치지 않게 배치한다.

## 2. 완성 화면

파란 첫 번째 노드와 보라색 두 번째 노드가 서로 다른 좌표에 표시된다.

## 3. 선수 지식

02-01의 직접 생성, Rect, addItem 호출 순서를 알아야 한다.

## 4. 이번 단계에서 사용하는 객체

두 개의 `ShapeNode`, 두 개의 `Rect`, 하나의 `Diagram`을 사용한다.

## 5. 핵심 개념

각 노드는 별도 객체이며 스타일과 bounds도 독립적이다. 같은 좌표를 사용하면 나중 항목이 앞 항목을 가릴 수 있다.

## 6. 파일 구성

`Step0202TwoNodes.jsx` 안에 두 ShapeNode의 생성과 스타일 설정이 모두 포함된다.

## 7. 구현 순서

첫 노드 생성/등록 → 두 번째 노드 생성/등록 → 각 색상 설정 → nodes.length 검증 순서다.

## 8. 전체 소스 코드

```js
directNode(diagram, { x: 25, y: 35, width: 48, height: 26 }, { text: "첫 번째 노드" });
directNode(diagram, { x: 92, y: 64, width: 48, height: 26 }, { text: "두 번째 노드" });
```

## 9. 소스 코드 상세 설명

두 Rect의 x, y 범위가 겹치지 않도록 충분한 간격을 둔다. 공통 helper는 반복되는 등록 실수를 줄인다.

## 10. 실행 흐름

초기화가 두 객체를 같은 Diagram에 차례로 추가하고 DiagramView가 두 항목을 z-order에 따라 그린다.

## 11. 상태와 데이터 흐름

배열을 별도 React state로 복제하지 않고 Diagram의 `nodes` getter를 진실의 원천으로 사용한다.

## 12. 정상 실행 기준

서로 구분되는 노드 2개, 연결선 0개, 콘솔 오류 0개가 보여야 한다.

## 13. 자동 검증 방법

02-02 선택 후 검증 패널 노드 개수와 Playwright의 `2개` 텍스트를 확인한다.

## 14. 수동 확인 항목

두 노드가 겹치지 않고 각각 드래그되는지 확인한다.

## 15. 자주 발생하는 오류

두 노드에 같은 객체 참조나 같은 bounds를 재사용하면 예상과 다른 이동이나 겹침이 발생할 수 있다.

## 16. 오류 해결 과정

각 노드의 identity와 bounds 값을 별도로 출력하고 Diagram nodes 배열의 길이를 확인한다.

## 17. 이전 단계와 비교

02-01의 단일 생성 패턴을 두 번 적용하고 개별 스타일과 배치를 추가했다.

## 18. 다음 단계

02-03에서 Factory shortcut이 생성과 등록을 함께 하는지 확인한다.

## 19. 연습 문제

세 번째 노드를 추가하고 기존 두 노드와 겹치지 않는 좌표를 계산해 본다.

## 20. 핵심 요약

여러 노드는 각각 별도 객체와 bounds를 가지며 Diagram nodes 배열이 실제 개수를 제공한다.
