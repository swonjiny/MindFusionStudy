# 09-04 ControlNode 대체 방식 비교

## 네 방식의 실제 차이

| 방식 | HTML DOM | 좌표 동기화 | 적합한 용도 |
| --- | --- | --- | --- |
| ControlNode | 예 | MindFusion 내장 | HTML 카드·버튼 |
| CompositeNode | 아니요 | MindFusion 내장 | 캔버스 기반 복합 도형 |
| React Portal | 예 | 직접 구현 | React 상태가 많은 UI |
| 외부 DOM Overlay | 예 | 직접 구현 | 간단한 보조 레이어 |

이 예제는 ControlNode와 CompositeNode를 같은 Diagram 모델에 추가하고, 그 위에 Portal과 일반
Overlay를 함께 표시합니다. CompositeNode는 `classFromTemplate`의 JSON 컴포넌트로 그려지므로
실제 HTML 버튼을 제공하지 않습니다.

## 선택 결론

09~11의 최종 방식은 ControlNode입니다. 실제 HTML이 필요하고 노드 이동·줌 좌표 동기화를
라이브러리가 처리하기 때문입니다. Portal과 Overlay는 React 컴포넌트를 자유롭게 쓸 수 있지만
Diagram 좌표를 CSS 좌표로 계속 변환해야 합니다.

## 정상 결과

- Diagram 노드 2개(ControlNode, CompositeNode)
- HTML DOM 3개(ControlNode, Portal, Overlay)
- 연결선 0개, 콘솔 오류 0개
