# 02-04 직접 생성 방식 노드 생성

## 1. 학습 목표

ShapeNode 생성, 속성 설정, Diagram 등록을 명시적으로 분리한다.

## 2. 완성 화면

주황 계열의 `직접 생성` 노드 한 개가 표시된다.

## 3. 선수 지식

02-03 Factory 자동 등록 방식을 알고 있어야 두 방식의 차이가 명확해진다.

## 4. 이번 단계에서 사용하는 객체

`new ShapeNode(diagram)`, `new Rect(...)`, `diagram.addItem(node)`를 사용한다.

## 5. 핵심 개념

생성자에 Diagram을 전달해도 자동 등록되는 것은 아니다. addItem은 직접 생성 방식의 필수 단계다.

## 6. 파일 구성

`Step0204DirectNode.jsx`와 `lessonDefinitions.js`의 `directNode` helper가 핵심이다.

## 7. 구현 순서

constructor 호출 → bounds 지정 → 텍스트/스타일 지정 → addItem → 검증 순서다.

## 8. 전체 소스 코드

```js
const node = new ShapeNode(diagram);
node.bounds = new Rect(55, 42, 58, 28);
node.text = "직접 생성";
diagram.addItem(node);
```

## 9. 소스 코드 상세 설명

Diagram 인자는 새 노드가 기본 모양과 스타일 설정을 참조하도록 한다. addItem이 소유 관계를 최종 확정한다.

## 10. 실행 흐름

독립 객체 생성 → 사용자 설정 → Diagram 컬렉션 추가 → DiagramView invalidation 및 렌더링 순서다.

## 11. 상태와 데이터 흐름

등록 전에는 로컬 객체, 등록 후에는 Diagram nodes 컬렉션의 항목이 된다.

## 12. 정상 실행 기준

주황색 직접 생성 노드 1개, 연결선 0개, 오류 0개여야 한다.

## 13. 자동 검증 방법

노드 수가 1로 바뀌고 재실행 후에도 1을 유지하는지 확인한다.

## 14. 수동 확인 항목

노드 위치, 크기, 텍스트, 테두리와 드래그 동작을 확인한다.

## 15. 자주 발생하는 오류

bounds를 지정하지 않거나 addItem을 빠뜨리면 보이지 않거나 기본 크기로 처리될 수 있다.

## 16. 오류 해결 과정

생성 직후 parent, bounds, addItem 이후 nodes.length를 차례로 확인한다.

## 17. 이전 단계와 비교

02-03의 Factory 내부 동작을 코드에서 명시적으로 드러냈다.

## 18. 다음 단계

## 19. 연습 문제

## 20. 핵심 요약

직접 생성은 더 세밀한 제어가 가능하지만 등록 책임이 개발자에게 있다.
