# 01-02 Diagram 화면 크기 설정

## 1. 학습 목표

DiagramView가 부모 크기를 따르는 원리와 고정 높이 방식의 차이를 이해하고 resize에 대응한다.

## 2. 완성 화면

`화면 채우기`와 `고정 높이`를 전환할 수 있고 우측 아래에 현재 너비와 높이가 픽셀로 표시된다.

## 3. 선수 지식

01-01의 Diagram과 DiagramView 관계, CSS의 `%`, `vh`, `min-height` 개념이 필요하다.

## 4. 이번 단계에서 사용하는 객체

`Diagram`, `DiagramView`, 브라우저 표준 `ResizeObserver`를 사용한다.

## 5. 핵심 개념

DiagramView 기본 스타일은 너비와 높이가 100%다. 따라서 자식보다 부모의 확정된 높이가 먼저 필요하다.

## 6. 파일 구성

`Step0102DiagramSize.jsx`가 독립 진입점이고 공통 `DiagramLesson.jsx`가 크기 방식 상태와 관찰자를 관리한다.

## 7. 구현 순서

1. 부모에 `min-height: 500px`을 준다.
2. 화면 채우기 높이에 viewport 계산식을 사용한다.
3. 고정 방식은 500px을 사용한다.
4. ResizeObserver로 contentRect를 읽는다.
5. 관찰자는 cleanup에서 해제한다.

## 8. 전체 소스 코드

```jsx
useEffect(() => {
  const observer = new ResizeObserver(([entry]) => {
    setSize(entry.contentRect);
  });
  observer.observe(hostRef.current);
  return () => observer.disconnect();
}, []);
```

## 9. 소스 코드 상세 설명

window resize 이벤트보다 ResizeObserver가 실제 부모 크기 변화를 직접 관찰한다. 사이드바나 전체 화면 전환에도 대응한다.

## 10. 실행 흐름

방식 선택 → CSS 클래스 변경 → 부모 크기 재계산 → ResizeObserver 알림 → 크기 Tag 갱신 순서다.

## 11. 상태와 데이터 흐름

`variant`는 크기 방식, `size`는 관찰된 픽셀 크기다. Diagram 모델 내용은 두 방식 모두 빈 상태로 유지된다.

## 12. 정상 실행 기준

두 방식을 전환할 수 있고 표시된 높이가 실제 영역과 일치하며 노드와 연결선은 0개여야 한다.

## 13. 자동 검증 방법

실행 화면, 검증 패널과 노드 수 0을 Playwright로 확인한다. 크기 Tag가 `0 × 0`이 아닌지도 확인할 수 있다.

## 14. 수동 확인 항목

브라우저 폭을 줄였을 때 canvas와 크기 Tag가 컨테이너 밖으로 나가지 않는지 확인한다.

## 15. 자주 발생하는 오류

부모 체인의 어느 한 요소라도 높이가 auto뿐이면 자식의 100%가 기대한 높이가 되지 않을 수 있다.

## 16. 오류 해결 과정

가장 바깥 레이아웃부터 실행 영역까지 계산 높이를 확인하고, 실제로 높이를 책임질 한 요소를 명확히 정한다.

## 17. 이전 단계와 비교

01-01은 최소 높이만 사용했다. 이번 단계는 크기 전략 전환과 실측값 표시를 추가했다.

## 18. 다음 단계

01-03에서 Diagram 자체 배경과 외부 CSS 격자를 구분한다.

## 19. 연습 문제

고정 높이 선택지를 400px, 600px 두 종류로 확장하고 표시 크기가 즉시 바뀌는지 확인한다.

## 20. 핵심 요약

DiagramView의 100% 크기는 부모 크기에 의존하며 ResizeObserver로 실제 결과를 확인할 수 있다.
